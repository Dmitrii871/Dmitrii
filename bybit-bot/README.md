# Bybit Trading Bot

Торговый бот для Bybit (API v5, бессрочные USDT-контракты). Открытый код, без подписок
и платных сервисов. Два режима: вход по совпадению индикаторов и маркет-мейкинг на спреде.

## Сначала прочитайте это

Бот — это исполнитель дисциплины, а не источник дохода. Он снимает эмоции, соблюдает
стоп-лоссы и не спит по ночам. Но зарабатывать он будет ровно настолько, насколько
прибыльна заложенная в него стратегия.

Проверить это можно и нужно **до** того, как рисковать деньгами:

```bash
python tools/backtest.py --demo --bars 3000
```

Прогон на случайном блуждании даёт минус примерно на величину комиссий. Так и должно быть:
на данных без структуры прибыльной стратегии не существует. Если бы демо показало плюс —
значит, в бэктесте ошибка. Это калибровка честности движка.

Три вещи, которые определяют результат больше, чем код бота:

1. **Комиссии.** Тейкер 0.055%, мейкер 0.02%. Круг тейкером = 0.11%. Сделка с тейк-профитом
   меньше 0.11% убыточна по построению — бот откажется запускаться с такой настройкой.
2. **Размер счёта.** Минимальный лот ETHUSDT — 0.01 ETH ≈ 25 USDT нотионала. На депозите
   в 40 USDT вы не можете ни дробить позицию, ни пересиживать просадку. Одна серия из
   четырёх стоп-лоссов по 0.8% — это уже заметная часть депозита.
3. **Плечо.** 3x означает, что движение рынка на 1% меняет ваш капитал на 3%. Плечо
   увеличивает и доход, и скорость потери депозита.

Самоматчинг (торговля бота с самим собой ради объёма) в этом проекте не реализован
и реализован не будет: это нарушение правил Bybit, ведущее к аннулированию наград и блокировке.

## Установка

```bash
git clone <repo> && cd bybit-bot
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env                  # вписать ключи
cp config.example.yaml config.yaml    # настроить параметры
```

**Ключи API.** Создайте с правами только `Trade` (Orders + Positions). Право на вывод
средств не включать никогда. Привяжите ключ к своему IP. Для тестов заведите отдельные
ключи на [testnet.bybit.com](https://testnet.bybit.com) — там торговля идёт фантиками.

## Установка

```bash
bash deploy/quickstart.sh
```

Скрипт создаёт виртуальное окружение, ставит зависимости, копирует конфиги
и прогоняет тесты. Вручную — четыре команды из раздела ниже.

**Сколько времени займёт**

| Шаг | Время |
|---|---|
| Установка Python и зависимостей | 10–15 мин |
| Ключи API на testnet | 5 мин |
| Первый сухой прогон | 2 мин |
| Бэктест и подбор параметров | 1–2 часа |
| Настройка VPS для круглосуточной работы | 20–30 мин |

До первого запуска в режиме логирования — около получаса. До запуска
на реальные деньги — неделя работы на testnet, и это не формальность:
именно там вылезают отказы биржи, разрывы связи и ошибки конфига.

## Что вы видите во время работы

Раз в `heartbeat_seconds` (по умолчанию 5 минут) бот печатает строку состояния:

```
14:32:10 INFO  bot | СТАТУС | цена 2463.29 | Buy 0.02 @ 2478.25 (P&L -0.2900) |
                     капитал 40.2734 USDT (+0.1200 за сессию) | ордеров 1 | спред 0.8 bp
14:32:10 INFO  bot.strategies.signal | Индикаторы {'rsi': 57.16, 'macd_hist': -0.59,
                     'pct_b': 0.58} | голоса: лонг=0 шорт=0
```

Видно всё: цену, позицию с текущим P&L, изменение капитала за сессию,
число висящих заявок и что показывают индикаторы. Всё то же пишется в `bot.log`.

Открытые ботом позиции появляются в вашем интерфейсе Bybit как обычные —
во вкладке «Позиции», с теми же TP/SL. Вы можете в любой момент закрыть их руками.

## Где запускать

**Ноутбук** — годится только для теста. Закрыли крышку, ушёл интернет,
уснула система — бот остановился. TP/SL при этом останутся на бирже
и позицию защитят, но новых сделок не будет.

**VPS за 3–5 $ в месяц** — правильный вариант для боевой работы.
Подойдёт любой минимальный тариф: 1 CPU, 1 ГБ памяти. Бот почти ничего
не потребляет. Берите датацентр поближе к серверам биржи (Сингапур,
Токио, Франкфурт) — меньше задержка на ордерах.

```bash
sudo cp deploy/bybit-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now bybit-bot

journalctl -u bybit-bot -f      # смотреть работу в реальном времени
sudo systemctl stop bybit-bot   # остановить
```

`Restart=on-failure` поднимет бота после сбоя, автозапуск переживёт
перезагрузку сервера. Для остановки без убийства процесса — файл `STOP`
в рабочей папке: бот доработает цикл и выйдет штатно.

## Порядок запуска

Проходите ступени по очереди, не перепрыгивая.

```bash
# 1. Бэктест: есть ли у стратегии прибыль на истории вообще
python tools/backtest.py --symbol ETHUSDT --interval 30 --bars 3000

# 2. Подбор параметров: тот же тест с другими TP/SL и порогом совпадения
python tools/backtest.py --symbol ETHUSDT --interval 30 --bars 3000 --tp 2.0 --sl 1.0 --confluence 3

# 3. Сухой прогон: testnet: true, dry_run: true — ордера только в лог
python -m bot.main --config config.yaml

# 4. Testnet: dry_run: false, testnet: true — реальные ордера, ненастоящие деньги
python -m bot.main --config config.yaml

# 5. Mainnet: testnet: false + флаг --live + подтверждение с клавиатуры
python -m bot.main --config config.yaml --live
```

Не переходите к шагу 5, пока шаг 4 не проработал хотя бы неделю без вмешательства.

## Выбор таймфрейма

Сравнение всех таймфреймов по одной метрике — во сколько раз типичная свеча
превышает стоимость круга:

```bash
python tools/timeframe_sweep.py --symbol ETHUSDT
```

| ТФ | свеча | / тейкер | / мейкер | сделок/мес |
|---|---:|---:|---:|---:|
| 3m | 5 bp | 0.47x | 1.29x | 86 |
| 5m | 7 bp | 0.61x | 1.67x | 65 |
| 15m | 12 bp | 1.05x | 2.89x | 43 |
| 30m | 16 bp | 1.48x | 4.08x | 43 |
| **1h** | **23 bp** | **2.10x** | **5.77x** | **22** |
| 4h | 46 bp | 4.20x | 11.55x | 11 |
| 1d | 113 bp | 10.28x | 28.27x | 2 |

Комиссия фиксирована, а движение растёт только как корень из времени.
Отсюда обе границы: ниже 15m запас над комиссией исчезает, выше 4h сделок
слишком мало, чтобы отличить работающую стратегию от везения.

**Рабочая настройка по умолчанию — 1h с `entry_type: post_only`:** запас 5.8x
и около 22 сделок в месяц, то есть выборка в 100 сделок набирается за 4–5 месяцев.

Перед сменой `interval` прогоните проверку — она отвечает на главный вопрос
коротких таймфреймов: превышает ли типичное движение свечи стоимость круга.

```bash
python tools/timeframe_check.py --symbol ETHUSDT --interval 3
```

На 3-минутке ETH медианная свеча около 5 bp, а круг тейкером стоит 11 bp.
Свеча вдвое меньше комиссии — вход рыночным ордером убыточен по построению.
Круг мейкером стоит 4 bp, и это единственный способ торговать на 3m:
поставьте `entry_type: post_only`.

Плата за это — часть сигналов не исполнится: ваша лимитка стоит в очереди,
а цена уходит без вас. Незалившиеся заявки снимаются через `entry_ttl_seconds`.

Чем короче таймфрейм, тем строже должен быть отбор: на 3m имеет смысл
`min_confluence: 3` (согласие всех трёх индикаторов) и длинный `cooldown_bars`.
Готовый профиль для 3m лежит в `config.example.yaml`.

## Подбор параметров

Перебор по истории всегда найдёт настройку, которая красиво заработала
в прошлом — при 60 вариантах несколько окажутся прибыльными случайно.
Поэтому оптимизатор делит историю пополам:

```bash
python tools/optimize.py --symbol ETHUSDT --interval 60 --bars 10000
```

**Обучение** — первые 60% истории, здесь идёт перебор.
**Проверка** — последние 40%, эти данные оптимизатор не видел.

Доверять можно только настройке, заработавшей на обеих частях. Инструмент
показывает, сколько вариантов из всех оказались прибыльными вне выборки:
если меньше трети — у стратегии нет устойчивого преимущества на этом рынке,
а удачные строки в таблице случайны.

Калибровка: на случайном блуждании с волатильностью реального ETH
оптимизатор отвергает все варианты. Он не выдумывает преимущество там,
где его нет.

**Про ширину стопа.** Стоп должен быть шире обычного шума, иначе позицию
закрывает рядовой фитиль, а не разворот рынка. Медианная часовая свеча ETH
около 59 bp — значит стоп в 40 bp находится внутри шума. Ориентир: 1,5–2
медианных диапазона свечи, точное значение подбирает оптимизатор.

## Торговый план: внешняя разметка как фильтр

Волновой анализ субъективен: одна свечная картина допускает несколько
равнозначных разметок, и счёт пересматривается при каждом новом экстремуме.
Поэтому бот **не размечает волны сам**. Он принимает готовый план как
гипотезу с тремя обязательными атрибутами.

```yaml
# plans/BTCUSDT.yaml
symbol: BTCUSDT
bias: long                  # смещение: против него бот не входит
invalidation: 125873        # цена, отменяющая сценарий
invalidation_side: above
expires: 2027-02-28         # срок годности разметки
levels:
  - {price: 73500, kind: support,    label: "фибо 0.382"}
  - {price: 83500, kind: resistance, label: "фибо 0.5"}
  - {price: 93500, kind: target,     label: "фибо 0.618 — цель волны b"}
```

Подключается через `plan_file` в конфиге. Что план делает:

- **Запрещает сделки против смещения.** Индикаторы дали шорт, а план говорит
  «вверх» — сделки не будет.
- **Добавляет один голос** при входе цены в зону уровня: отскок от поддержки —
  довод за лонг, упор в сопротивление — за шорт. Ровно один, то есть сам по
  себе план позицию открыть не может: порог согласия — два индикатора.
- **Подтягивает тейк-профит** к ближайшему уровню по ходу сделки, но не ближе
  половины расчётного тейка.
- **Самоотключается**, когда цена пробивает уровень отмены или истекает срок.
  Отключение окончательное до конца сессии, с записью в лог.

План никогда не отменяет риск-менеджмент и не открывает позиции.

В репозитории лежат два плана — по BTC и ETH, составленные по волновой
разметке стороннего аналитика. **Это гипотезы, а не прогнозы.** Проверяйте
и обновляйте их сами; тест `test_shipped_plans_load_and_are_consistent`
следит за внутренней непротиворечивостью.

### Сетка Фибоначчи

```bash
python tools/fib.py --low 41127 --high 125873 --price 78000
python tools/fib.py --solve 0.382=73500 0.618=93500     # восстановить чужую разметку
```

Обратная задача нужна, чтобы проверить чужой график: по двум подписанным
уровням она показывает, от каких экстремумов построена сетка. Если
восстановленные точки не совпадают с реальными экстремумами — разметка
подогнана.

## Диагностика счёта

Собирает всё, что нужно для настройки бота под ваши реальные условия:

```bash
python tools/diagnose.py --symbol ETHUSDT
```

Пишет `diagnostics.json`: ваша **фактическая** ставка комиссии (а не справочная),
режим маржи и режим позиций, торговые фильтры символа, состояние позиций
с расстоянием до ликвидации, статистику по 100 последним закрытым сделкам
(винрейт, профит-фактор, матожидание, медианное время удержания) и стоимость
фандинга в годовых.

Ключи API читаются из `.env`, никуда не отправляются и в отчёт не попадают.
Идентификаторы счёта вырезаются. Готовый файл можно безопасно показывать.

## Стратегии

### `signal` — вход по совпадению индикаторов

Те же индикаторы, что у вас на графике: RSI 14, MACD 12/26/9, Bollinger %B 20/2.
Каждый голосует «лонг», «шорт» или воздерживается. Вход только при согласии
`min_confluence` индикаторов из трёх. Выход — по take-profit и stop-loss, которые
выставляются **на самой бирже**: позиция защищена, даже если бот упадёт или пропадёт связь.

Сигналы считаются один раз на закрытии свечи, а не на каждом тике — это убирает
дёрганье внутри бара и лишние комиссии.

**Направление.** По умолчанию бот торгует в обе стороны: перепроданность даёт
лонг, перекупленность — шорт, разворот сигнала против открытой позиции её закрывает.
Ограничить одной стороной можно через `direction: long_only` / `short_only`.

Бот работает в **одностороннем режиме** (One-Way): лонг и шорт по очереди, не
одновременно. Если символ переключён в хедж-режим, бот откажется стартовать —
там Bybit требует `positionIdx` у каждого ордера.

**Асимметрия шортов.** Ставка фандинга на ETHUSDT обычно положительная: лонги
платят шортам каждые 8 часов. Для позиции, живущей дольше суток, это заметная
разница в пользу шорта. `tools/diagnose.py` показывает вашу фактическую ставку
в годовых.

Бэктест выводит результат раздельно по лонгам и шортам — если прибыль приходит
только с одной стороны, это видно сразу.

### `maker` — заработок на спреде

Бот держит лимитные заявки с обеих сторон от середины рынка и зарабатывает разницу
между ценой покупки и продажи. Котировки смещаются при накоплении инвентаря: набрали
длинную позицию — котировки съезжают вниз, чтобы охотнее продать.

Стратегия отказывается стартовать, если `spread_bps` не покрывает комиссию мейкера.
Главный риск — движение рынка в одну сторону: вас наберут по одной стороне, и вы
останетесь с позицией против тренда. Поэтому `max_inventory_usdt` обязателен.

## Риск-контур

Проверяется на каждом цикле, до отправки любого ордера:

| Параметр | Что делает |
|---|---|
| `max_position_usdt` | Потолок нотионала позиции |
| `max_daily_loss_usdt` | Просадка за календарный день UTC, счётчик обнуляется в 00:00 |
| `min_free_margin_ratio` | Порог свободной маржи, защита от ликвидации |
| `max_orders_per_hour` | Защита от разгона комиссий при сбое логики |
| `kill_switch_file` | `touch STOP` — аккуратная остановка без убийства процесса |

Разделение намеренное: стратегия думает о прибыли, риск-менеджер — о том, чтобы
депозит пережил серию её неудачных решений.

**Предстартовая проверка.** До первой сделки бот считает, хватит ли маржи
на позицию размера `max_position_usdt` при заданном плече. Если после её
открытия свободной маржи осталось бы меньше `min_free_margin_ratio`, бот
откажется стартовать и назовёт максимально допустимое значение:

```
max_position_usdt=60 при плече 3x требует 20.00 USDT маржи. После открытия
свободной маржи осталось бы 9.5% при пороге 25% — бот остановился бы сразу
после входа. Поставьте max_position_usdt не больше 41.
```

Без этой проверки бот открыл бы позицию и тут же упал по риску,
оставив её висеть без управления.

## Защита от типовых поломок

Список собран из разборов реальных отказов торговых ботов. Каждый пункт
закрыт в коде и покрыт тестом.

| Поломка | Что происходит без защиты | Как закрыто |
|---|---|---|
| **Дубль ордера** | Ответ биржи потерялся в сети, бот повторил отправку — открылись две позиции вместо одной | Свой `orderLinkId` у каждого ордера. При неясном сбое бот сначала спрашивает биржу, долетел ли ордер, и только потом повторяет |
| **Протухшие данные** | Поток молча застыл: ошибки нет, цена часовой давности, бот торгует по ней | Возраст последней закрытой свечи проверяется на каждом цикле; торговля приостанавливается, через 10 циклов подряд снимаются заявки |
| **Расхождение часов** | Часы VPS уходят на секунды в сутки, биржа отвергает подписи с ошибкой, которая про часы не говорит | Сверка с временем биржи при старте, порог 2 секунды, в ошибке — готовая команда исправления |
| **Ключ не от того контура** | Ключ testnet против mainnet — поток невнятных ошибок авторизации | Ошибки авторизации выделены в фатальные: бот останавливается сразу с понятным сообщением, а не долбит биржу неверной подписью |
| **Лимит запросов** | Повторы синхронизируются и снова бьют в лимит | Экспоненциальная задержка со случайным разбросом |
| **Частичное исполнение** | Залилась половина заявки, остаток висит, позиция тихо растёт сверх расчёта — а TP/SL считались от исходного размера | Остаток входной заявки снимается, как только позиция открылась. Заявки на закрытие при этом не трогаются |
| **Минимальная сумма ордера** | Количество прошло по `qtyStep`, а сумма меньше минимума — отказ биржи | Проверяются оба фильтра: и минимальное количество, и минимальная сумма |
| **Округление вверх** | Количество округлилось вверх — ордер больше, чем позволяет депозит | Количества округляются только вниз, цены — к ближайшему тику |
| **Заглядывание в будущее** | Бэктест показывает прибыль, реальная торговля — убыток | Незакрытая свеча отбрасывается. Прогон на случайном блуждании даёт минус ровно на комиссию — это подтверждает отсутствие утечки |
| **Расхождение состояния** | Бот помнит одно, на бирже другое | Бот не хранит состояние позиций: каждый цикл читает их с биржи заново |

## Структура

```
bot/
  indicators.py        RSI, MACD, Bollinger %B — чистый Python, формулы как в TradingView
  exchange.py          обёртка Bybit v5: округление до tick/step, ретраи, dry_run
  models.py            типы, которыми обмениваются слои
  risk.py              лимиты и аварийная остановка
  strategies/
    signal.py          вход по совпадению индикаторов
    maker.py           маркет-мейкинг на спреде
  main.py              цикл, CLI, защита от случайного запуска на mainnet
tools/backtest.py      бэктест с учётом комиссий, просадки и профит-фактора

```
